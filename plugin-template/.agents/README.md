# Shared Skills and Agent Roles

Instructions shared by Claude Code, Codex and Gemini CLI. Root [AGENTS.md](../AGENTS.md) comes first, and the LightSpeed organisation rules it links to come before it.

| Location | Purpose |
| --- | --- |
| `skills/<name>/SKILL.md` | Skills: `test`, `validate`, `changelog`, `branch-validation` |
| `skills/speckit-*/SKILL.md` | Spec Kit skills for Codex, generated by Spec Kit |
| `roles/<name>.md` | Role instructions; see the [role inventory](roles/INVENTORY.md) |

## How Each Tool Finds Them

- **Claude Code**: each folder in `.claude/skills/` (other than `speckit-*`) is a relative symlink to the folder here. `.claude/agents/<role>.md` tells the agent to read `roles/<role>.md`.
- **Codex**: reads `skills/` here directly. `.codex/agents/<role>.toml` loads the role.
- **Gemini CLI**: reads `skills/` here directly. `.gemini/agents/<role>.md` loads the role.

Edit behaviour here. Change an adapter only when its name, description or tools change. Keep the symlinks: Git stores them, so do not replace them with copies.

## Limits

A skill or role describes how to do the work. It does not grant permission to push, publish, label, release or contact anyone; that comes from the user, and the organisation's rules still apply.
